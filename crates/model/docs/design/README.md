# The model: design

Recorded intent for what knowledge-architect reads of a project: how it is built internally, and why.
The designs this Component did not keep are `register@model@rejected`, each cited by the heads whose
argument covers it, and `skill@knowledge-architect-decision-recording@head-shape` owns the shape.

The heads are grouped by subject, one subdocument per subject, listed below. A subject heading carries
no decision; each decision is one level-three head below it.

- [The crate and its interface](the-crate.md): what the crate holds, and what it offers across its boundary
- [Paths and homes](paths-and-links.md): the `path`, `register` and `planned` references
- [Anchors and Components](anchors.md): what an anchor is, what a Component carries, and how anchors stay apart
- [The walk](git-and-the-walk.md): how git supplies the tree a run reads
- [Entities, ids and headings](entities-and-headings.md): what an entity is, where a slug defines one, and how an unresolved reference is reported
- [Reading a file](run-model.md): what a parse failure is
- [What is prose](prose.md): which bytes of each kind of file are prose
- [Registers and their homes](registers.md): how a register is declared and how an entry is read
- [Plan documents](plan-documents.md): the plans directory, its specs and milestones, and their items
- [The agent configuration as entities](agent-configuration.md): the harnesses a project serves, and what the entity table reads of them
- [Reference spans](reference-lints.md): which spans are references
- [Generated files](generated-files-and-fixes.md): the generated indexes and the list of files that are generated
