# `worklist` prints each agent's load and never a group's

## Summary

`cargo klarch worklist --out <dir>` prints, per agent, its words and the names of its groups, and
names a group's own load only in the notice for a group above the bound. Which subjects are near
the bound, the question a split of a design home asks, has no command.

## Details

### What

`write` in `path@core@src/cli/worklist.rs` prints one line per agent:
`agent-<n>  <words> words  <group>; <group>`. `design@core@clusters-packed-under-a-word-bound`
records the notice for a group above the bound only.

Instance: W1 and C2 of the retrospective of the session that moved two design homes to the
directory shape, 2026-10-25. To find the subjects near the bound, and to compare the clusters
before and after the split, the session ran `worklist --bound 1 --out <dir>`, which forces every
group into a notice and writes one unused agent directory per group, 41 after the split.

### Why it matters

The split rule of `skill@knowledge-architect-decision-recording@current-design` names the bound,
and the load per group follows from the tree with no judgement, per
`goal@knowledge-architect@mechanical-tasks-are-the-tool-s`.

### What would close it

The default output, or an option of `worklist`, prints each group's name and load without writing
agent directories, with a test, its class in the changelog given as
`issue@knowledge-architect@command-output-is-not-declared-a-contract` leaves open.
