# What a project audit puts on the owner's list, narrowed to the closed list, on one branch

## Summary

A cluster of the issue record: two entries on items the audit sends the owner that the record
settles, which one branch closes together. Each member's own entry holds its observation, its reason
and its closing work; this entry holds only that they go together.

## Details

### What

The members:

- `issue@agent-skills@a-head-in-the-wrong-component-goes-to-the-owner-though-the-record-settles-the-component`
- `issue@agent-skills@texts-send-the-owner-more-than-the-closed-list`

They go on one branch because both apply `primer@question-authority` to the outcome table of
`skill@knowledge-architect-project-audit`, and one cites the other. Found by a triage of the whole
issue record on 2026-11-11, which read every entry against the tree and sized it: each member was
judged to have a clear path to closing, and to be more work than a fix of a few dozen lines.

### Why it matters

Each member's cost of being left is its own entry's. Taken one per branch, each pays again the
grounding, the review and the merge that the others share, so the cluster is the unit the roadmap
orders.

### What would close it

One branch that closes every member. A member closed alone, or found to need a design discussion,
leaves this list in the commit that closes it or moves it; the entry closes with its last member.
