# The first test for a losing alternative admits every rival of a head that earned its place as an interface

## Summary

`skill@knowledge-architect-decision-recording@losing-alternatives` opens with "Most designs not
kept earn no entry", and its first test admits a design that "would change an interface others
consume". Every rival of a head that earned its entry by entry test 1 changes that interface, so
the test admits all of them. Whether the derivation sentence of test 3 limits test 1 reads two
ways, and one harvest applied it both ways.

## Details

### What

- The section: "**Most designs not kept earn no entry.**"; test 1, "it would change an interface
  others consume, as entry test 1 of `primer@design-heads` defines it"; and, after the tests, "Test
  3 is the load-bearing one. … What decides an entry is whether the refutation can be derived again
  inside that round", which can be read to bind every test or test 3 alone.
- `design@agent-skills@losing-alternatives-filter` lists test 1 as standing alone and argues only
  from derivation.
- The instance: a harvest in rootpoint admitted three losing alternatives of an interface head on
  test 1 alone, and left two others that would change the same interface in the deleted plan as
  arguments a reader derives again; the decision-record reviewer reported the inconsistency, and the
  repair added three more entries. Reported in that session's retrospective, analysed at the intake
  of 2026-10-24.
- The rival proposed there: test 1 reads "and its refutation cannot be derived again from the head
  that cites it". Another rival: keep test 1 broad and drop the opening sentence.

The suspected mechanism, in one sentence: the head's list and its argument part, so a reader
applying the list admits what the argument would leave out.

Re-entry point: the next change to the tests for a losing alternative, or the owner's word.

### Why it matters

`rejected@agent-skills@every-losing-thread-recorded` is `live`, with the owner's judgement that the
filter is "still a little imperfect"; a filter read two ways grows the `rejected` homes unevenly,
against `goal@knowledge-architect@design-is-recorded-with-its-arguments`.

### What would close it

A discussion under `skill@knowledge-architect-design` that states which tests the derivation limits,
in the skill and in `design@agent-skills@losing-alternatives-filter`.
