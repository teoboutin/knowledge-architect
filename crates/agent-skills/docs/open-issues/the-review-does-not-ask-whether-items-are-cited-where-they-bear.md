# The installed review does not name the two questions the goals now ask of it

## Summary

`goal@agent-skills@reviews-judge-what-no-tool-can` asks that the installed text owe, before every merge, a review naming two questions:
whether each recorded item that bears on the work is cited where it bears, and whether the work departs from what bears on it. The installed
review skill names neither as such, and no plan document schedules the work.

## Details

### What

`git grep -n 'cited where' -- crates/agent-skills/content/skills/review/` returned nothing when the goal was written. The design-conformance
axis reads a plan document against the record, and at a merge only under a condition, and code review axes judge shape and claims; which axis
should carry each question is not decided. `goal@knowledge-architect@records-reach-their-reader` also asks that a session read the two listings
before a change that reverses a decision, and that the retrospective ask how that review fared; neither was read against the installed text.

### Why it matters

The goal is unmet until the text names both, against `goal@knowledge-architect@agents-work-without-drift`: a departure with every reference resolving
passes each gate, so only a review catches it.

### What would close it

The installed review names both questions on an axis of its table, with what a session reads before a reversal and the retrospective's question,
argued from a target project's side as `path@agent-skills@CLAUDE.md` says.
