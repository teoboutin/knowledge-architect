# Improving performance has no installed activity, nor a benchmark procedure

## Summary

The development skill guards a declared performance-critical path against a regression, by a
measurement before and after a change, per `design@agent-skills@performance-opt-in`. Making code
faster, as a task of its own, has no installed skill, and the workflow ships no procedure for a
benchmark a project could run.

## Details

### What

A project that wants a path faster has no installed procedure for it: how to choose the workload,
take a measurement that two runs agree on, and record the before and after as evidence. thaum keeps
such a procedure of its own, a bench tool with recorded runs and workload fingerprints. A
performance review axis was considered and withdrawn: a reviewer that judges speed by reading code
cannot reproduce its findings.

### Why it matters

`goal@knowledge-architect@agents-get-a-complete-workflow` asks the workflow to cover the activities
of a target project, and improving performance is one a project meets once a path matters. Without a
procedure, each session improvises the measurement, and a claimed improvement carries no evidence a
reader can take again.

### What would close it

A design session, under `skill@knowledge-architect-design`, on an installed activity for improving
performance and its benchmark procedure, taking thaum's bench tool as the case to generalise from,
and the work it plans.
