# No design head argues that an installed instruction prevails over one the configuration adds, nor that the installed text may rely on the harness's own mechanisms

## Summary

`design@agent-skills@installed-skill-takes-precedence` decides that no skill from outside the
installed set and the project takes the place of an installed skill. Three statements beside it are
argued by no head: that the same holds of an instruction the configuration adds, that an installed
instruction may defer to such an instruction, and that the installed text may rely on the harness's
own mechanisms.

## Details

### What

The statements, each with what it bound:

- "a skill or an instruction the configuration adds, outside the installed set and the project,
  the harness's own included, never takes the place of an installed skill or instruction for an
  activity the set covers, unless an installed instruction itself defers to it." For a skill,
  `design@agent-skills@installed-skill-takes-precedence` holds it. For an instruction, the words
  "or an instruction" and "or instruction" bound the installed text to let no user-level
  instruction, plugin's instruction or instruction of the harness take the place of an installed
  instruction, and no head argues it. The exception, "unless an installed instruction itself defers
  to it", admitted an installed instruction that hands a case to an instruction of the
  configuration, and no head holds it.
- "it may rely on the harness's own mechanisms." It admitted an installed skill that relies on a
  mechanism of the `claude` harness, such as the dispatch of an agent. No text states it. It follows
  by a reading of `goal@knowledge-architect@serves-one-kind-of-project`, which asks that a target
  project's agents run under the `claude` harness, with
  `goal@knowledge-architect@agents-get-a-complete-workflow`, under which an agent "needs no
  instruction from outside what knowledge-architect provides and what its project adds": a mechanism
  of the harness is no instruction.

Instances seen: one, of an instruction of the configuration followed in place of a project's own.
`issue@agent-skills@the-agent-configuration-skill-names-no-place-for-a-local-uncommitted-instruction`
records a session that followed a block of the harness's system prompt, written for cloud sessions,
and skipped the draft pull request this repository's root `CLAUDE.md` asks for. The instruction it
displaced is the project's, not an installed one. No instance is recorded of an installed
instruction displaced, nor of an installed instruction that defers to one of the configuration.

The suspected mechanism, in one sentence: the precedence was argued for a skill, on the harness
listing a plugin's skill beside an installed one, and the words on an instruction were written
beside it with no rival named and no fact against one.

Re-entry point: the next design discussion that changes
`design@agent-skills@installed-skill-takes-precedence`, or the discussion that closes
`issue@agent-skills@the-agent-configuration-skill-names-no-place-for-a-local-uncommitted-instruction`,
which decides where an instruction of one machine's configuration goes.

### Why it matters

A session whose configuration holds an instruction on an activity the installed set covers has no
installed text that says which it follows, and `design@agent-skills@installed-skill-takes-precedence`
covers a skill only. A session that argues an installed skill out of relying on a mechanism of the
harness, as an instruction from outside the workflow, finds no head that states the reading above.

### What would close it

A design discussion under `skill@knowledge-architect-design` that argues each of the three against
its nearest rival: each becomes a member of `design@agent-skills@installed-skill-takes-precedence`
where that head's argument covers it, a head of its own where it passes an entry test of
`primer@design-heads`, or is dropped, with the reason in the commit that deletes this entry. An
instruction added to the installed text for the precedence needs the evidence
`design@agent-skills@behaviour-additions-need-real-use` asks.
