# Only the design and setup skills state what they expect of the owner

## Summary

The retrospective skill carries two expectation sets, the design skill's and the setup skill's,
whose one item the owner stated. The other installed skills state none, so a retrospective finding
about them cannot be judged against one.

## Details

### What

An expectation set lists the assumptions an installed skill makes about the owner's behaviour and
the project's shape, each naming what degrades when it does not hold. The owner: "It is probably a
model worth following for the other installed skills (not necessarily with the same set)." Each
set states assumptions about the owner's behaviour, which are the owner's to state, so each is
written with the owner, item by item, and lands in the retrospective skill, with its restatement
in the README of the agent-skills component.

A case the planning skill's set would decide: a rootpoint session worked six slices of a milestone in
one branch, by the owner's direction, where the planning skill defines a slice as "one branch and
one PR". Each slice's review re-read the whole branch, as if before a merge. With no set, its
retrospective reported the direction as a gap of the skill; an assumption that a slice is one branch
would have placed it outside the skill's scope. Analysed at the intake of 2026-10-24.


### Why it matters

`design@agent-skills@expectation-set-bounds-scope` makes the set the scope test for every edit of an
installed skill. A skill without one has no test: every finding about the owner's behaviour reads as
a gap, and its text can grow to absorb each one, which `design@agent-skills@behaviour-additions-need-real-use`
exists to prevent.

### What would close it

A set for each installed skill that has assumptions worth stating, ruled by the owner, in the
retrospective skill and the README; or the owner's ruling that a skill needs none.
