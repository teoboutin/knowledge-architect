# No design head argues that an installed text which fails a goal is a defect provable by reading

## Summary

A goal held that an installed text failing a goal of knowledge-architect is repaired on reading,
with no evidence from use. The goal no longer holds it, and
`design@agent-skills@behaviour-additions-need-real-use`, which lists the classes of defect provable
by reading, does not list this one.

## Details

### What

The statements, verbatim from the goal on real use as
`git show cb8d5a22:docs/goals.md` holds it, each with what it bound:

1. "An installed text that fails a goal of knowledge-architect, every Component's included, is a
   defect provable by reading." It bound a class of defect repaired without evidence from use.
2. "Admits, for instance: an instruction added on a defect found by reading the installed text
   against a goal." It bound the same class, for an added instruction.

`design@agent-skills@behaviour-additions-need-real-use` and
`path@agent-skills@fragments/admission-evidence.md` list the classes provable by reading, and
"fails a goal" is in neither. The session wrote the statement and the owner approved it as goal
text, so it is the session's decision and no ruling of the owner.

Suspected mechanism: the class was stated in a goal, which bound outright, so the head that lists
the classes never took it as a member.

The re-entry point: an instruction on how an agent behaves proposed on the ground that the
installed text fails a goal, with no instance from use.

### Why it matters

`goal@knowledge-architect@the-workflow-improves-through-real-use` has real use as the test of how
an agent behaves under the workflow. A goal now states a direction and leaves when, how much and by
what means to design, so "fails a goal" read widely admits any instruction a session derives from a
goal, which is the class that head exists to hold to evidence.

### What would close it

`design@agent-skills@behaviour-additions-need-real-use` takes the class as a member with its
bounds, or refuses it with the reason, through `skill@knowledge-architect-design`, and the fragment
follows the head.
