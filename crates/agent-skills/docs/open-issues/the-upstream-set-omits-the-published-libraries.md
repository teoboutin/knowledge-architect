# The set of what a finding sends upstream names the installed text and the checker, and no published library

## Summary

`design@agent-skills@installed-fix-goes-upstream` closes the set of what a project sends upstream to
the installed text and the checker. A target project also takes the gates library, and from the
mutation crate's first release that crate too, through its maintenance crate, without owning them.
Whether a finding whose fix lies in one of those libraries takes the same route is not stated.

## Details

### What

The head reads: "The set is closed to the two: the installed text, which the project never edits,
[...] and the checker it pins are the text and code a project takes from the workflow without owning
them". The primer's section `primer@met-outside-the-task` routes an item "whose fix lies in the
installed text or in the checker" to the retrospective's workflow file, and says nothing of a
library. The gates library, `knowledge-architect-gates`, is published and pinned by every Rust
target project's maintenance crate today; the first slice of the milestone that ships the development skill adds
`knowledge-architect-mutate`, pinned the same way. Found at that slice's design audit, by the record
search, which graded the head `bears`.

### Why it matters

A finding on a library a project pins and cannot edit takes, under the current text, one of the
outcomes the head argues each loses such a finding: handled now with nothing the project can edit,
or an issue in a register the upstream cannot read. It strains
`design@agent-skills@installed-fix-goes-upstream` and
`goal@knowledge-architect@the-workflow-improves-through-real-use`.

### What would close it

A reading of the head's argument against a finding on the gates library: if the argument covers it,
the head and the primer's section name the published libraries in their set, through
`skill@knowledge-architect-design`, since the head's set is stated as closed; if it does not, the head
says why the libraries are outside.
