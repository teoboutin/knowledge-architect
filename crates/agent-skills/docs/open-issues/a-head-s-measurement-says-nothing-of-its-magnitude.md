# Does a head carry the magnitude of the measurement it rests on?

## Summary

The installed rule on what a head stands on asks for "the measurement it rests on, with the
command that takes it again", and says nothing of the magnitude. Where the corpus is the project's
own record, which every change grows, a magnitude in a head is stale soon after it is written.
This repository's root `CLAUDE.md` keeps the magnitude out of a head; the installed text does not.

## Details

### What

The rule is `path@agent-skills@fragments/head-ground.md`, which the primer and the decision-recording
skill host, and `design@agent-skills@standing-argument-in-head` decides it.

Instance: W5 of the workflow file and P1 of the project file of the retrospective of the session
that built `klarch worklist`, 2026-10-25. The harvest wrote measured magnitudes into heads, word
loads taken by a hand script before the command existed and an entry count, and four review axes
found figures stale at the commit or not reproduced by the named command. The root rule,
`instructions@where-knowledge-goes`, was read at the session's start and needed at the harvest.

The proposal: one sentence in the installed rule, that a magnitude over a corpus that changes stays
in the commit that took it, and the head keeps the claim, the command and the direction that would
reopen the decision; this repository's paragraph then cut to its own exceptions. The rival: a
sentence in this repository's development skill, at its commit step, leaving other projects to
their own rule.

### Why it matters

A head whose figure is stale argues from a number no reader can reproduce, against
`goal@knowledge-architect@design-is-recorded-with-its-arguments`. The sentence would sit in a
fragment the primer hosts, so it is weighed against `design@agent-skills@primer-limit`.

### What would close it

A discussion under `skill@knowledge-architect-design` that rewrites
`design@agent-skills@standing-argument-in-head` with the sentence, or records why the magnitude is
left to each project.
