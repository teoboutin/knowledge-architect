# Check design: Entities, ids and headings

## Entities, ids and headings

### The goals home cites only a goal or a register's home of the root, and every other reference there is refused `##goals-home-cites-only-goals-and-root-homes`

In the goals home, which the root alone carries, per `design@model@goal-register-carried-by-the-root-alone`, its
goals and its head alike, a reference is refused unless it is a `goal` reference or a `register`
reference to a home of the root. A refused reference gets a finding of its own, beside any finding
its resolution gives, except a `path` or a `planned` reference, which is judged by this finding
alone, since its own repairs name forms refused here: a register's home of another Component,
every other kind, `design`, `issue`, `rejected`, `tripwire` and `path` among them, and every
harness reference, which names a skill, an agent or a section. The finding names the repair: a goal
or a register's home of the root, or the sentence rewritten so it names no entry,
never the span with its backticks removed, per `design@agent-skills@plain-text-is-no-repair`. Every
other finding of the reference check that would name a reference form refused in a goals home
names this repair instead: an unanchored path, an anchor in the kind position
and a link from a file that is no navigation home name it always; a malformed span names it unless
its own repair is the form of a goal or of the `goal` register's home, which name no anchor; the
resolution finding of a refused reference names it, and that of an admitted one unless it is an
undefined goal or a register name the project does not know, whose repairs name no other form; a
link whose refused target lies outside its file's directory names it; an id written outside its
reference form names it where no form the citation check admits there names the id, and otherwise
offers that admitted form; a reference written without backticks names it where its form is refused
there, and otherwise asks for the backticks. Every other document cites in whatever direction its
subject asks.

A goal is the owner's statement and changes only through the owner, per
`goal@the-owner-decides`, while agents write, move and close design heads,
issues and skill sections on their own. A goal that cites one of them is touched when it moves, and
a goal tied to a Component is tied to a shape of the project: the Component can be split or
replaced while the purpose stays. No goal refines another, per
`design@agent-skills@no-goal-refines-another`, so a goal cites another only where its own words
name it. A goals home's head is held to the same rule, on the owner's argument, given as the owner's view, that
a design head is cited nowhere in a goals home: no argument stands for a goals home's citation
of the head on the lifecycle of goals, since that lifecycle rests on what the goal-setting skill says, and
a consumer's goals home cites none of this project's heads either.

The rule is a check, not a rule the goal reviewer applies alone, since it is mechanical, per
`goal@tasks-a-tool-does-better-are-the-tool-s`, and the same in every project, per
`design@check@the-regime-has-no-opt-out`. Its nearest rival, the one-way rule over every citation,
`rejected@check@citation-direction-checked`, covered every document for an acyclicity that only the
record search's clusters would use. This rule covers the goals home alone and stands on the
stability of goals, which that entry's reason does not reach, since its reason names the clusters'
acyclicity alone. It is the one exception to `design@check@no-citation-direction-rule`. A
relocation still edits no document: the goals home cites the root, which no manifest edit moves.

### No rule on the direction of a citation is checked outside a goals home `##no-citation-direction-rule`

A search's clusters are built per `design@query@record-is-every-register-entry`. 

Membership of a cluster reads an edge either way, so a rule that citations run from goals down to
issues would buy acyclicity alone, which serves a transitive membership that merges the clusters.
A goals home is the one place a direction is checked, for a reason of its own, the stability of a
goal, per `design@check@goals-home-cites-only-goals-and-root-homes`.
The design this decision did not keep: `rejected@check@citation-direction-checked`.
