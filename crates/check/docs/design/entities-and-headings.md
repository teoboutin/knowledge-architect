# Check design: Entities, ids and headings

## Entities, ids and headings

### A goals home cites only a goal or a register's home of its own anchor or of a Component enclosing it, and every other reference there is refused `##goals-home-cites-upward-only`

In a goals home, its goals and its head alike, a reference is refused unless it is a `goal` or a
`register` reference whose anchor is the home's own or a Component whose directory holds the
home's anchor, the root included. A refused reference gets a finding of its own, beside any finding
its resolution gives, except a `path` or a `planned` reference, which is judged by this finding
alone, since its own repairs name forms refused here: a goal or a register's home of a nested or a sibling
Component, every other kind, `design`, `issue`, `rejected`, `tripwire` and `path` among them, and
every harness reference, which names a skill, an agent or a section. The finding names the repair:
a goal of the home's own or an enclosing Component, or the sentence rewritten so it names no entry,
never the span with its backticks removed, per `design@agent-skills@plain-text-is-no-repair`. Every
other finding of the reference check that would name a reference form refused in a goals home
names this repair instead. Five findings do: an unanchored path, a retired slug form and an anchor
in the kind position name it always; an id written outside its reference form names it where no
form the citation check admits there names the id, and otherwise offers that admitted form; a
reference written without backticks names it where its form is refused there, and otherwise asks
for the backticks. The findings that still name a refused form there are a defect of the code
against this rule, `issue@check@some-findings-in-a-goals-home-name-a-form-refused-there`. Every
other document cites in whatever direction its subject asks.

A goal is the owner's statement and changes only through the owner, per
`goal@knowledge-architect@the-owner-decides`, while agents write, move and close design heads,
issues and skill sections on their own. A goal that cites one of them is touched when it moves, and
a goal tied to a nested Component is tied to a shape of the project: the nested Component can be
split or replaced while the purpose above it stays. A goal refines a goal of its own Component or of
one enclosing it, so the citations of refinement point that way, as a nested Component's goal
refines its intermediate Component's, per
`design@agent-skills@no-installed-rule-on-when-an-intermediate-component-exists`. A
goals home's head is held to the same rule, on the owner's argument, given as the owner's view, that
a design head is cited nowhere in a goals home: no argument stood for the root goals home's citation
of the head on the lifecycle of goals, whose lifecycle rests on what the goal-setting skill says, and
a consumer's goals home cites none of this project's heads either.

The rule is a check, not a rule the goal reviewer applies alone, since it is mechanical, per
`goal@knowledge-architect@mechanical-tasks-are-the-tool-s`, and the same in every project, per
`design@check@the-regime-has-no-opt-out`. Its nearest rival, the one-way rule over every citation,
`rejected@check@citation-direction-checked`, covered every document for an acyclicity that only the
record search's clusters would use, and would fail every goal that refines another. This rule
covers goals homes alone, admits a refinement, and stands on the stability of goals, which that
entry's reason does not reach, since its reason names the clusters' acyclicity alone. It is the one
exception to `design@check@no-citation-direction-rule`, and to the relocation that
`design@check@every-path-names-its-anchor` says edits no document: a move that changes which
Components enclose a goals home turns its citations of the former enclosing Component into
findings, which strains `goal@check@relocation-needs-only-goal-changes`.

### No rule on the direction of a citation is checked outside a goals home `##no-citation-direction-rule`

A search's clusters are built per `design@query@record-is-every-register-entry`. 

Membership of a cluster reads an edge either way, so a rule that citations run from goals down to
issues would buy acyclicity alone, which serves a transitive membership that merges the clusters.
A goals home is the one place a direction is checked, for a reason of its own, the stability of a
goal, per `design@check@goals-home-cites-upward-only`.
The design this decision did not keep: `rejected@check@citation-direction-checked`.
