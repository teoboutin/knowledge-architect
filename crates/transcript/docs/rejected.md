# Rejected designs

The designs transcript did not keep, and why.

### A transcript reader that refuses a line type or a value it does not know `##strict-transcript-reader`

`live`. Over every transcript of the machine the reader was designed on, Claude Code 2.1.306 to
2.1.310, each version added a line type, an attachment type or a key with the feature it shipped,
and a parser that refused the unknown would have failed on each; a third-party parser,
claude-code-log, printed a warning on every line of the new types, its issue 116 reporting that
"Claude Code 2.1.x emits a few new top-level JSONL types" it did not recognise. The window's types are re-taken with the command of
`design@transcript@transcript-format-tolerated-and-reported`. The harness documents the
format as internal and liable to change between versions.

### A line placed by its fields alone, a line no field places left unlabelled or read as its dispatcher's `##fields-alone-place-every-line`

`live`. An interrupt the harness writes with no `interruptedMessageId` and a subagent file's
dispatcher lines carry the same key beyond those of every chain line, `promptId`, over every transcript of the owner's machine, Claude Code
2.1.306 to 2.1.316, on 2026-11-07, re-taken with the command of
`design@transcript@transcript-labels-in-code`. No field tells them apart, so a reader of fields alone
reads the owner's interrupt in a subagent file as its dispatcher's text, and every run over such a
session asks for an unlabelled line to be reported that no release of the reader can place.
Naming the shapes in the transcript reviewer's text instead leaves each session to apply a text
rule by its own reading, which `design@agent-skills@transcript-extraction-is-the-checker-s` refuses.
