# Slice 4: the deliberation of its design audit

## Threads

### The command prints the named package first, then the other selected crates by package name `##consumer-crate-order`

Raised by the record search of this slice's design audit, which graded
`design@model@assembled-crates-in-the-manifest-s-order` `conflicts`: the command renders over a
consumer's resolved graph, and no file a consumer receives states the publisher's order of the
Components, since `expected_preamble` writes the categories and no crate order. Put to the owner at
the design audit as Q1, a choice between two shapes stated in full:

- A, chosen: the named package first, then the other selected packages in the order of their
  package names. Nothing built changes; the output holds the publisher's entries, the crates under a
  category in another order than the publisher's assembled file, near the alphabetical rival that
  `design@model@assembled-crates-in-the-manifest-s-order` defeats for that file.
- B: each crate's preamble gains a line listing the project's changelog crates in the manifest's
  order, which the checker writes and checks and the command follows. The output equals the
  publisher's file for those versions; slice 3's `expected_preamble`, its check and their tests
  change, every crate's preamble changes when a changelog crate is added, removed or moved, and a
  graph holding two versions of the project's crates whose lines differ needs a rule for which
  wins.

Final state: approved. The owner chose A after the session's explanation of both shapes, with A as
the session's default: A over B, the owner ranked a preamble and a check left as built above an
output in the publisher's crate order, which no goal ranks. Its shape is in "Decided design" of this
slice's `README.md`.
