## New thread: #transcript-files-per-discussion

**Why it matters.** Today the checker allows exactly one `transcript.txt` per plan document (`crates/model/src/manifest.rs:92` and `crates/model/src/tree.rs:531`). So keeping several discussions apart takes a checker change, not only a change to the skill text.

**Proposal.** A plan document's directory holds `transcripts/`, with one file per design discussion, named by the date of the discussion's opening message:

```
docs/plans/milestones/<id>/
├─ README.md
├─ deliberation.md
├─ search/
├─ transcripts/
│  ├─ 2026-11-02.txt       the discussion that designed the milestone
│  └─ 2026-11-20.txt       a rediscussion before slice 2's turn
└─ <slice>/
   └─ transcripts/
      └─ 2026-12-04.txt    a discussion held at slice 3's design audit
```

- A second discussion on the same date takes a suffix: `2026-11-20-2.txt`.
- One discussion that spans several sessions stays one file, with its sessions in order, as today.
- A discussion that rewrites several slices, or the milestone's `README.md`, is filed under the milestone. One that rewrites only one slice is filed under that slice.

**Rivals:**

- Numbered flat files at the top (`transcript-2.txt`): these are ordered, but a reader cannot tell when each discussion took place.
- Keeping the bare `transcript.txt` for the first discussion: this avoids a migration. The cost is two names for one kind of file, and the checker has to accept both.

**Consequences:**

- The checker's set of allowed files changes, in the `model` Component.
- A project that already holds a `transcript.txt` must rename it, which takes a Migration entry in the changelog. This repository holds none at the moment: the only live spec, `path-quickfixes`, has no transcript.
- A later reversal would touch stored data, so the premortem runs, per `skill@knowledge-architect-design@decision-authority`.
