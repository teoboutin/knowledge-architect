## #doc-gate-denial: the gate sets `RUSTDOCFLAGS="-D warnings"` (default)

What I measured on the scratch crate:

| command | broken link | exit |
| --- | --- | --- |
| `cargo doc --no-deps` | warning | **0** |
| `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps` | error | 101 |
| `[lints.rustdoc] broken_intra_doc_links = "deny"`, plain `cargo doc` | error | 101 |
| `build.rustdocflags = ["-D","warnings"]` in `.cargo/config.toml` | error (4 errors) | 101 |
| the same config, with `RUSTDOCFLAGS="--cfg foo"` exported | **0 errors** | 0 |

The three shapes:
- **(a) The gate sets the variable (default).** It catches every rustdoc warning, with nothing the project must declare. This is the pattern of the clippy gate's `-- -D warnings`.
  - Cost 1: in the gate, the variable replaces any `RUSTDOCFLAGS` the caller exported and any `build.rustdocflags` the project configured. A project whose docs need a flag adds it to the gate's `envs` in its own list.
  - Cost 2: switching between a plain `cargo doc` and the gate rebuilds the docs of every workspace crate. That took 0.77 s here.
- **(b) A plain `cargo doc`, plus an ask that each project declares `[lints.rustdoc]`.** Defeated: a plain `cargo doc` exits 0 on a broken link. A project that has not yet adopted the ask would get a gate that passes silently, which fails the first criterion.
- **(c) `--config build.rustdocflags=…`.** Defeated by the last row of the table: an exported `RUSTDOCFLAGS` silently drops the deny.

**A cost (a) accepts:** rustdoc also emits `missing_docs`, as I measured. One missing doc therefore fails two gates, `clippy` and `doc`. Adding `-A missing_docs` to the gate would avoid that, but it adds gate logic only to avoid a duplicate report.
