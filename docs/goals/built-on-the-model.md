# knowledge-architect goals: What is built on the model

The goals on what knowledge-architect builds on the documentation model: the checks, the rendering and the tools.

## A target project's documentation stays consistent with its code and with itself `##documentation-stays-consistent`

In a target project, agents change code faster than a review alone can follow. Reviews and audits
judge what the documents mean: whether the code departs from what they state, and whether two
documents agree. The checker and the tools that list the recorded items, as knowledge-architect
ships them, support them and judge no meaning, whatever a project's own checks may do. A mechanical
rule, such as that a flag a document names is one the program declares, judges none.

A tree that passes the checker conforms, in the texts the checker reads, to every rule the checker
holds for every project and to every rule the project declares, save those the project switches off
by a declaration, and nothing cited there is missing. Conformance is established by running the
checker, not by a reviewer remembering the rules.

## A target project adds checks of its own, which run with the checker's `##projects-add-their-own-checks`

A target project whose conventions the checker's own rules do not cover adds checks of its own, to
guard its own design intent. It adds them with what knowledge-architect provides, and with no
change to knowledge-architect. They run and report with the checker's own.

## A target project's documents render as one linked site `##documents-render-as-a-linked-site`

The documents of each target project render as one site of that project, in which each reference
is a link to what it names, so a reader follows a reference by a link. A project can host that site with what it
releases.

## A task that a tool does at a lower cost, or with a better result, is done by a tool knowledge-architect provides, once knowledge-architect's owner has taken the task in `##tasks-a-tool-does-better-are-the-tool-s`

The agents of a target project carry out tasks, those the workflow asks among them. Where a tool does such a task at a lower
cost to the agent than the agent's own means, or reaches a better result, and knowledge-architect's
owner has taken the task in, knowledge-architect provides a tool that does it. So each session gets
the same result, and none builds its own means again.

This reaches a task whose result follows with no judgement from what the project holds, the
workflow's rules and what the session gives it. It also reaches searching, updating and verifying
what a project holds, its documents, its recorded items, its history and what its past sessions
said, where the judgement stays the agent's.

A task is taken in by a decision of knowledge-architect's owner, never because the workflow asks it.
