# No head argues what becomes an ask of every target project, nor the asks that no goal states

## Summary

`goal@knowledge-architect@serves-one-kind-of-project` says that knowledge-architect asks more of a
target project than its four conditions, and names two asks: a git repository, and agents under the
`claude` harness. `goal@knowledge-architect@the-owner-decides` gives knowledge-architect's owner
each addition, tightening or removal of an ask. No goal and no design head states how a tool or a
decision becomes an ask, what a quality tool is, or the asks on the use of the workflow with the
checker, on the gates and on the merge verdict. Each statement below binds nothing until a head
argues it.

## Details

### What

The statements, verbatim from the goals that held them, each with what it bound.

From the goal `setup-brings-quality-tools`, which no longer exists:

- "each is an ask", said of "the quality tools [...] whose generic part knowledge-architect's owner
  has taken in". It bound every target project to adopt each quality tool taken in.

From `goal@knowledge-architect@serves-one-kind-of-project`, which no longer holds them:

- "An ask that binds every target project is added by a design decision of knowledge-architect, or
  by taking in a quality tool, which then becomes an ask so that every target project adopts it".
  It bound how an ask enters.
- "A quality tool, in every goal of knowledge-architect, is a tool that judges the project's
  quality mechanically, such as a gate or a check". It defined the term the statement above uses.
- "a tool that serves efficiency, such as a command that rewrites history, becomes no ask; a
  procedure of the installed workflow is none". It bound which tool taken in is not asked of a
  project. `design@knowledge-architect@mutation-command-host` applies it to the hand mutation.
- "The installed text states each ask, those listed here included." It bound the installed text.
  `issue@knowledge-architect@the-target-project-and-its-asks-are-stated-to-no-adopter` holds the
  work.
- "the project uses both the workflow and the checker. A project that uses the checker alone is a
  target project that does not follow this ask". It bound every target project to install the
  workflow.
- "the project is a git repository, with its `.git` at or above the project's directory". The goal
  keeps the ask of a git repository, and no longer says where its `.git` sits.
- "it runs every gate it owes, from one command, through a library that knowledge-architect
  publishes to run a project's gates". It bound every target project to the gates library.
  `design@agent-skills@gates-convention` states the command as a recommendation of the setup skill,
  and `design@agent-skills@maintenance-crate-ask` asks the crate that holds it.
- "that command judges whether the gates let a branch merge, with the same invocation in every
  target project." It bound one merge invocation.
  `issue@gates@the-library-has-no-merge-verdict` holds the work in the library.
- "How an ask is met in every target project, such as the name of the command and its invocation
  for a merge, is a design decision of knowledge-architect; how one project meets the rest is its
  own." It bound where the shape of an ask is decided.

Suspected mechanism: these statements were scope held in two goals, and the goals now state a
direction and leave to design what a head can argue. No head was argued for them when they left,
since no rival and no fact that defeats it were found for the rule that a quality tool taken in
becomes an ask.

### Why it matters

A session that takes in a tool cannot tell from the record whether every target project is then
asked to adopt it. The hand mutation is held to be no ask by a rule no text states any longer. A
head that states an ask on the gates stands on no argued rule of what an ask is, and the merge
invocation differs between the projects that use the gates library.

### What would close it

A design discussion under `skill@knowledge-architect-design` that argues each statement, or drops
it with its reason: the rule of what becomes an ask, with the definition it needs; and each ask
that no goal states, recorded as a head on the owner's word where it is the owner's, per
`goal@knowledge-architect@the-owner-decides`.

### Re-entry point

That discussion, at the latest when a branch next takes in a tool that judges a project's quality,
or when the work of `issue@knowledge-architect@the-target-project-and-its-asks-are-stated-to-no-adopter`
starts.
