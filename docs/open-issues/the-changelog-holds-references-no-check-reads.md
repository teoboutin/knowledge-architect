# The changelog holds references that no check reads, where it is meant to hold none

## Summary

The root CHANGELOG.md is outside the walk, on the owner's argument that it faces outward, as a
crate's page does, so a span in it is a name or a syntax example and never a pointer the checker
judges. Its entries still write references, and two heads ask a Migration entry to cite a section
as a reference.

## Details

### What

On the owner's word, at the review before the merge of the slice that made the register `goal` the
root's alone, the changelog left the walk, per
`design@knowledge-architect@the-changelog-is-outside-the-walk`, and the owner stated that it
should hold no reference to real content. The skip row is built; the rule is not. The changelog
holds 77 lines with a backticked span holding an `@`, counted by `grep -c` over CHANGELOG.md on that
branch, some of the spans references and some syntax examples. `design@knowledge-architect@changelog-entries` says an entry
for a change of the rules recorded content must meet "cites the section that brings that content to
them ... as a reference, so the move of the pin runs it", and
`design@agent-skills@audit-triggers`, which the installed project-audit and setup skills follow,
keys an audit at a pin move on a Migration entry "citing an axis's section".

### Why it matters

A reference that no check reads dangles in silence when its entry is renamed, the failure
`design@knowledge-architect@crates-io-page-file` keeps a crate's page from holding a reference to
avoid; and a consumer's session reads the changelog of every version its pin crosses, where a span
shaped like a reference reads as one. It strains `design@knowledge-architect@changelog-entries`.

### What would close it

A design discussion under `skill@knowledge-architect-design` decides how an entry names what it
cites, a section of an installed skill among them, with no reference; the two heads are rewritten
to that outcome, the installed text that keys on a Migration entry's citation with them; and the
`Next release` section is written so. Whether the released sections' spans are respelled is part of
that discussion, since a released section's content never changes; the owner's earlier view, that
writing a name as its reference in a released section is a change of structure, is the case
`issue@knowledge-architect@the-released-changelog-section-rule-has-no-argument` records. Re-entry point: the next change
that writes a Migration entry citing a section of the installed text, or earlier on the owner's
word.
