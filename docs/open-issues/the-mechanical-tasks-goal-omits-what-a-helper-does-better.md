# The goal on mechanical tasks does not cover an action a command would make more efficient or better

## Summary

`goal@knowledge-architect@mechanical-tasks-are-the-tool-s` covers a task whose result follows with no
judgement. The owner holds that it leaves out a case that should also be ground for taking a command in,
and will rework its wording.

## Details

### What

On the owner's word, at the goals of `model`: the goal does not cover an action asked of an agent that no
mechanical task performs, and that a command could make more efficient by making it mechanical, or by a
helper that performs complex logic to give a better result. The keyword search of
`issue@query@no-command-searches-the-entries-or-lists-an-audit-s-work` is the second case: its result does
not follow with no judgement, so the goal does not reach it. The owner's lead is to change the goal, or to
add another goal for these conditions.

The same lead gives the goals of the `query` Component, which `spec@component-split@consumers-out` drafts:
to make agents more efficient by commands that query the scanned documents, a tool that does not query
them going in a crate for its own subject.

### Why it matters

No goal gives a ground for taking in a command of this kind, so such a command is argued from nothing the
root states, against `goal@knowledge-architect@agents-get-a-complete-workflow`.

### What would close it

The goal reworded, or another goal added, under `skill@knowledge-architect-goal-setting`, on the owner's
ruling.
