# This repository's own skills, agents and commands are not checked for a generic part to ship

## Summary

`goal@generic-tools-and-procedures-are-shipped` has the generic part of a tool or a procedure that a
target project sets up shipped once knowledge-architect's owner takes it in. This repository is a
target project too. The retrospective now asks each session for the tools it sets up, per
`design@agent-skills@tool-report-moment`, but the tools this repository already holds were never
checked for a generic part.

## Details

### What

This repository's own skills (`skill@klarch-development`, `skill@klarch-release`,
`skill@klarch-retrospective-intake`), its agent definitions, its `CLAUDE.md` files and the commands
of its maintenance tool, `path@xtask@README.md`, each read for the part a session would find
generic to every project that carries out the activity, and whether knowledge-architect already
ships it, as the retrospective's question asks of a tool set up in a session.

### Why it matters

A tool set up before the question existed reaches the owner only when the owner remembers it, so the
goal's purpose, one toolchain for every target project, stays unmet for those.

### What would close it

The check done once, each finding put to the owner, who decides whether to take it in, per
`goal@the-owner-decides`; each part taken in opens its own issue or plan document.
